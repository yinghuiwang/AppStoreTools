# 仪表盘 Command Workspace 设计规格

**日期：** 2026-07-21  
**状态：** 已通过设计评审，待实现计划  
**范围：** Web UI 首页 `/` 仪表盘及任务日志交互

## 目标

在保留任务历史的前提下，让首页同时回答三个问题：

1. 自动化现在是否健康，哪些事项需要处理？
2. 常用上传、构建和检查操作能否快速发起？
3. 相比在 App Store Connect 网站手工编辑，已经节省了多少时间？

最终采用 **Command Workspace** 方向：左侧固定导航，中间为仪表盘和任务流，右侧为可展开的实时日志抽屉。首页优先服务高频操作用户，同时保留健康摘要和效率分类账。

## 视觉与布局

沿用现有 Web UI 的黑曜石背景、琥珀主色、DM Sans + Fira Code 字体和紧凑信息密度。页面不再使用独立的插画右栏，首屏空间全部用于工作区。

桌面布局：

```
固定导航 64px | 仪表盘/任务流（自适应） | 日志抽屉 390px
```

- 固定导航：仪表盘、上传、构建、设置等入口，当前入口使用琥珀色状态。
- 仪表盘顶部：当前 profile、时间范围（7/30/90 天）、profile 范围筛选。
- 摘要行：预计节省时间、成功率、失败任务投入时间。
- 运行中任务：固定在任务历史上方，展示阶段、百分比和已运行时长。
- 任务历史：保留最近 20 条，显示任务类型、profile、状态、耗时、日志入口和重试/诊断入口。
- 日志抽屉：从任务行右侧展开，主工作区向左收缩；关闭后恢复原宽度。移动端抽屉改为右侧全宽覆盖层，保留关闭按钮。

## 仪表盘数据

### 摘要指标

摘要按时间范围和 profile 筛选实时重算：

- **预计节省时间**：只统计 `done` 任务，逐任务计算 `max(固定人工基准 - 工具实际耗时, 0)` 后求和。
- **成功率**：`done / (done + error + canceled)`；没有已结束任务时显示 `--`，不显示误导性的 100%。
- **失败任务投入**：`error` 和 `canceled` 任务的实际耗时总和，明确标注“不计入节省”。
- **运行中**：`pending` + `running` 数量，作为活动流入口而不是节省统计的一部分。

初始固定人工基准（分钟，不提供用户编辑入口）：

| 任务类型 | 人工基准 |
| --- | ---: |
| 元数据上传 `metadata` | 30 |
| 构建上传 `build` | 45 |
| 更新说明 `whats-new` | 10 |
| 内购上传 `iap` | 25 |
| IAP 审核截图 `iap-review-screenshots` | 20 |
| URL 更新 `urls` | 8 |
| 工具更新 `update` | 5 |

实际耗时使用现有 `created_at` 到 `completed_at`（运行中使用当前时间）计算。基准和计算规则在“估算说明”弹层中可见，避免把估算误认为 ASC 的实测数据。

### 任务筛选

筛选条件：时间范围、profile、任务类型、状态。筛选只影响仪表盘摘要和历史列表，不改变任务存储内容。默认使用当前 profile、近 30 天、全部任务类型和全部状态。

## 快速操作

仪表盘中间区域提供常用入口：上传全部、更新元数据、上传截图、构建并发布、检查环境。入口打开现有表单对应的侧滑参数面板，确认后创建现有任务类型；上次成功提交的非敏感参数可作为初始值，凭证、密钥和本地路径不写入浏览器持久存储。

桌面端支持可选的键盘入口：`Cmd/Ctrl+K` 搜索动作或 profile，`M/S/B/C` 分别聚焦元数据、截图、构建、检查。输入框获得焦点时不捕获这些快捷键。

## 右侧实时日志抽屉

### 打开与切换

任务行点击“日志”后：

1. 右侧抽屉展开，宽度固定 390px；中间工作区收缩但不被遮挡。
2. 使用同一个抽屉切换任务，不创建多个浮层。
3. 关闭或按 `Escape` 后抽屉收起，保留当前筛选和历史滚动位置。
4. 再次打开同一任务，从日志末端开始显示；已完成任务加载完整历史。

### SSE 数据流

前端使用现有 `GET /api/task/{task_id}/stream`：

- 维护当前任务的最后日志序号 `lastSeq`，首次打开从 `after=0` 开始。
- 每条 `log` 事件追加到日志 DOM，并以事件 ID 更新 `lastSeq`。
- `progress` 事件更新中间任务卡片的百分比和阶段文本。
- `done`、`error_event`、`canceled` 事件更新抽屉连接状态和任务行状态。
- 连接断开时保留已有内容，使用 `Last-Event-ID` 重连；按序号去重，避免重复日志。
- 任务结束后保留日志内容，不再继续轮询；SSE 心跳超时显示“正在重连”。

### 自动滚动规则

默认状态是“自动跟随”：打开抽屉后滚动容器到底部；收到新日志时只要用户仍在底部，就平滑滚动到最新行。

以下任一行为会暂停自动跟随：

- 用户向上滚动或拖动滚动条，离开底部阈值（底部 8px）；
- 用户在日志区域进行文本选择；
- 用户点击“仅错误”或复制操作后，视图不应被强制跳到底部。

暂停后，抽屉底部固定显示“有 N 条新日志 · 回到最新”。点击“回到最新”时滚动到底部、清除新日志计数并恢复自动跟随。用户手动滚回底部也恢复跟随。

## 后端接口与边界

新增只读摘要接口（建议放在 `routes_api.py`）：

`GET /api/dashboard/summary?range=30d&profile=&kind=&status=`

返回摘要、筛选后的任务列表和固定基准版本。接口不读取完整日志，只返回任务元数据，避免首页加载成本随日志长度增长。现有 `/api/tasks/recent` 保留用于兼容其他页面，首页改用摘要接口或对应 HTML partial。

任务日志继续复用现有 SQLite `task_logs(seq, message, created_at)` 和 SSE 路由，不新增日志表。日志抽屉只在用户打开任务时建立 EventSource，关闭或切换任务时关闭旧连接。

### 异常处理

- 摘要接口参数非法时返回 400，并保留页面上一次有效结果。
- 找不到任务时关闭抽屉并显示“任务不存在或已被清理”。
- SSE 断线最多按递增间隔重连；重连失败时显示连接错误，但不清空日志。
- 复制日志失败时显示非阻塞提示，不影响实时流。
- 没有历史任务时显示空状态和快速操作入口；没有成功任务时节省时间显示 `0m`，并解释尚无可计入任务。

## 文件边界

预计修改：

- `src/asc/web/templates/index.html`：Command Workspace 页面布局、筛选、摘要、右侧日志抽屉。
- `src/asc/web/templates/base.html` 或新的 dashboard JS 片段：抽屉开关、SSE、自动跟随和快捷键逻辑；保持通用任务日志函数兼容。
- `src/asc/web/routes_api.py`：摘要查询接口和筛选参数校验。
- `src/asc/web/tasks.py`：复用任务数据，必要时新增按条件汇总的纯函数，不改变已有任务表结构。
- `tests/test_web_server.py`：摘要接口、筛选、空状态、SSE 断线续传相关测试。
- `tests/test_web_tasks.py`：固定基准节省时间、成功率、失败投入的汇总单元测试。

不在本次范围内：

- 不接入 App Store Connect 网站的真实人工耗时采样。
- 不允许用户编辑人工基准。
- 不改造其他表单页的日志面板布局。
- 不增加浏览器端持久化敏感参数。

## 验证标准

- `pytest` 全量通过，现有任务、SSE、HTMX 刷新测试不回归。
- 摘要计算对 `done`、`error`、`canceled`、`pending`、`running` 各状态有覆盖。
- SSE 断线后使用 `Last-Event-ID` 重连不会重复或丢失日志。
- 日志区域在桌面和移动断点均不遮挡任务上下文；用户上滚后不会被新日志强制拉回底部。
- 使用浏览器手动验证：打开/切换/关闭抽屉、自动跟随暂停与恢复、过滤条件、重试入口和空状态。
